# CLAUDE.md

Vasco — CLI for AI web research. Python 3.12+, managed with `uv`.

## Run

| Task | Command |
|---|---|
| Install | `uv sync` (`--group dev` for tests); add `--extra browser` on the host that runs `vasco browser-server` (camoufox lives in the `[browser]` extra, server-only) |
| CLI | `uv run vasco <subcommand>` |
| Daemon | `uv run vasco serve` (resident `vascod`; systemd units in `contrib/systemd/`) |
| Tests | `uv run --group dev pytest -q` |
| Lint / format | `uv run ruff check .` / `uv run ruff format .` |

> **Don't run `ruff` + `pytest` manually as a final verification step** — `.git/hooks/pre-commit` already runs `ruff format` + `ruff check --fix` on staged `.py` files and the full `pytest` suite, aborting the commit on failure. The hook is the authoritative gate. Run them by hand only for *fast feedback while iterating* (e.g. a single file/test you just touched), not to "verify" before handing off. Functional smoke checks the hook can't cover (CLI runs, daemon/socket behavior, config loading) are still worth running.

## Invariants

- **Fetch envelope is the contract.** Same shape across `fetch_one`, `extract`, `cache.get`. The shape is built in exactly one place — `vasco/envelope.py` (`base_envelope`/`success_envelope`/`failure_envelope`); core fetch and every adapter call these (adapters get their thin delegator pair from `adapters._common.envelope_builders(mode_used, content_type)`). Adding/renaming a field means editing `vasco/envelope.py` **and** the `cache.py` columns (incl. `_FETCH_CACHE_ADDED_COLUMNS` for the ALTER back-fill) + `_hydrate_cache_hit`; `tests/test_cache_roundtrip.py` fails CI if a builder field has no cache column (this caught `image`/`modified` being silently dropped).
- **vascod is the shared coordinator; the envelope is also a wire contract.** `vasco serve` runs a resident daemon (`vasco/service/`) that owns one `Config`+`Cache` and serves the full API (`search`/`fetch`/`fetch_many`/`extract`/`answer`/`map`) over a UNIX socket, adding cross-consumer **single-flight dedup + per-domain rate-limiting** (only meaningful because every consumer funnels through one process). It sits **in front of** `browser_server` as a client (two independent systemd peers — neither owns the other; preserves browser crash isolation). MCP and claudinho are clients; the **CLI stays in-process** (debuggable ground-truth path, and the cache is already shared via the SQLite *file*). The envelope crosses the socket as JSON unchanged — `protocol.PROTOCOL_VERSION` versions the *transport*, the envelope stays the single source of truth. A *fetch failure* is still a `failure` envelope over the wire (`ok=true`); `ok=false` means a transport/daemon error. The wire shape lives in exactly one place: `vasco/service/protocol.py` (claudinho vendors a copy of `PROTOCOL_VERSION` + framing and guards against drift at runtime). vascod is **stateless between deadline-bounded requests** — it survives host suspend/resume with no special handling; a wedged browser is healed by `browser_server`'s existing watchdog. **Key-dependent ops resolve keys from config when routed.** All six tools route through vascod, so the LLM call in `answer` (DeepSeek) executes in the *daemon's* process, which does **not** inherit the MCP/shell env — set `answer.api_key` in `~/.config/vasco/config.yaml` (env vars like `DEEPSEEK_API_KEY` only reach a tool when it runs in-process, e.g. the CLI). Restart `vascod.service` after editing config.
- **`fetch_one` never raises.** Failures are first-class output via a `failure` object whose `reason` is a `FailureReason` enum value. New failure modes go in `errors.py` first, then `fetch.bot_detect.classify` learns to produce them. Two reasons are **produced outside `classify`** because `classify` only sees raw HTML: `PARSE_FAILED` is **adapter-produced** (a 200 OK whose source-specific parser lost its structural anchor — adapters raise `errors.AdapterParseError` at the anchor); `EMPTY_BODY` is **core-fetch-produced post-conversion** (a 200 OK from any tier that trafilatura converted to zero words — an unrendered shell even the browser tier couldn't fill). Both carry short transient TTLs.
- **Content adapters distinguish scraper-rot from empty results.** Each adapter (olx, mercadolivre, realestate, google_shopping, aliexpress, shopify, shopee, steam, phabricator, gitlab) parses a structural anchor (OLX `__NEXT_DATA__`, ML/vivareal/Shopee schema.org JSON-LD `Product`, Google Shopping `<product-viewer-entrypoint>`, AliExpress rendered `card-out-wrapper`/`/item/` cards — it parses the rendered DOM, not embedded JSON, since AliExpress ships none; Phabricator task `og:title` `T<id>` anchor / search `ul.phui-oi-list-view`). **Anchor absent/unparseable → raise `AdapterParseError` → `PARSE_FAILED` failure** with a short, agent-readable message (never raw HTML). **Anchor present but zero items → `success` + `"no_results"` in `warnings`** (a genuinely empty search). A *detail/product* page parsing to zero items is always rot (it should yield exactly one). This is what stops a site markup change from silently caching a `result_count: 0` success forever. **AliExpress detail is the documented exception**: its product spine is the URL `product_id` + the open reviews API (no clearance needed), so a *walled* PDP still returns a useful product (id + reviews) flagged with a `page_blocked` warning — it only fails when the page is blocked *and* reviews are unavailable. **Shopify's anchor is a platform JSON endpoint** (`.js` / `products.json` / `suggest.json`), not HTML — its `fetch_html` requests the endpoint directly; a known-domain endpoint that 200s but isn't Shopify-shaped JSON → `PARSE_FAILED`. Shopify adds **probe semantics on top**: for an *unconfirmed candidate* domain a miss raises `NotShopify` so the dispatcher **falls through to a normal fetch** (a non-Shopify lookalike must never become a failure), with a 200-but-not-JSON definitively negative-memoizing the domain and a 404 left ambiguous (bad handle vs. not Shopify → no memo). Probe verdicts are **persisted** in the cache's `adapter_probe` table (TTL'd), so a domain is probed at most once across all processes — re-probe cost isn't paid per CLI run. **Phabricator's documented exception**: it's an unauthenticated HTML scraper (the Conduit API needs a token), so it reads **public data only** — a *restricted* task (anonymous → login wall / policy-exception page) returns a clear **`LOGIN_REQUIRED`** failure, not the misleading `PARSE_FAILED`; the auth-wall markers are checked only on an anchor-less page so a public task whose comments merely discuss permissions never false-fires, and a 404 task is `NOT_FOUND`. **GitLab** fetches the public `/api/v4` JSON (project `id`+`path_with_namespace` / issue+MR `iid`+`title` anchors; no auth, so a private project just 404s → honest `NOT_FOUND`, never an escalation surface) and **reuses Shopify's probe pattern for self-hosted detection** but keyed by **full host** (a GitLab instance is subdomain-specific) rather than registered domain: `gitlab.com` ∪ `cfg.adapters.gitlab.domains` are known, an unknown host on a claimable URL is probed (non-JSON <500 → memo False; valid object → memo True; ambiguous/5xx → `NotGitLab` fall-through), and its dispatcher branch runs **after** Shopify because a bare `/a/b` project shape overlaps Shopify's `/products/x` candidate. The `/-/issues|merge_requests/` markers are probed on **any** host, but the broad **bare-project** shape is probed only on a **forge-hinted** host (`_forge_hint`: a `gitlab`/`git`/`code`/… hostname label) so vasco doesn't spray `/api/v4/` at every site (others → `domains` config). It fetches via its **own minimal-header httpx client** (`_api_get`, not `fetch_html`) — the chain's headers 403 on self-hosted WAFs — so it never uses the browser pool. README (project) and notes (issue/MR) are best-effort. (Per-adapter detail in [docs/adapters.md](docs/adapters.md).)
- **URL normalization is the cache key.** `urls.normalize_url` (in `vasco/urls.py`) is load-bearing — changing it invalidates every cached entry. Besides lowering, sorting params, and stripping a curated tracking-param denylist (`utm_*`/`mtm_*` prefixes plus ad-click, social-share, email, and Alibaba `spm`/`scm` IDs — `_TRACKING_EXACT`/`_TRACKING_PREFIXES`; conservative by design, ambiguous params like `ref`/`source`/`id` are kept), plus a **host-scoped** complement (`_HOST_TRACKING_RULES`) that drops names too generic to be globally safe but unambiguous tracking on one site (MercadoLivre `pdp_filters`/`sid`, OLX homefeed tags like `page`/`rec`/`gallery_id` — OLX paginates with `?o=`, so `page` is a click tag there but stays globally kept), it folds AMP variants (`?amp=1`, `?output=amp`, `/amp/` path segments) and collapses all YouTube URL forms (`youtu.be`, `m.youtube.com`, local TLDs, `/embed/`, `/shorts/`) to bare `youtube.com/watch?v=<id>`. It also **unwraps known redirect/link wrappers** (`_REDIRECT_RULES`: Facebook `l.php?u=`, Google `/url?q=`, `out.reddit.com?url=`, …) to the real destination *before* the rest of normalization runs — so a wrapped page is fetched/cached under its true key (and a wrapped YouTube/Wikipedia link still canonicalizes). Unwrapping is host-scoped (+ path-scoped where the host is also a normal site) and only fires when the extracted target is an absolute http(s) URL, so a regular page carrying a `?url=` param is never touched; nesting is bounded (`_MAX_UNWRAP_DEPTH`). Tests in `tests/test_normalize.py` are table-driven.
- **Auto-mode escalation lives in `fetch.core._do_fetch_html`.** Chain is `http → browser → browser+mobile → wayback`. Per-tier wall-clock caps (`HTTP_MAX_BUDGET` 5s, `BROWSER_MAX_BUDGET` 12s, `MOBILE_MAX_BUDGET` 5s, `WAYBACK_MAX_BUDGET` 6s — defined in `fetch.urlutils`) are the *primary* budget — the chain naturally takes up to ~28s for a full run. The caller-supplied `deadline` (default 30s) is a kill-switch hard upper bound, not the timing users feel in practice. Each tier's effective deadline is `min(global_deadline, now + tier_cap)`. `cache.bump`'s `failure_count` tracks consecutive failures of the *preferred* mode only; non-preferred-mode bumps don't move the counter. Strategy is keyed per-**route** (`urls.route_key(url)`: registered_domain + first path segment, e.g. `vivareal.com.br/aluguel/*` vs `vivareal.com.br/imovel/*`), so page-types within a domain learn independent starting tiers. The starting tier is `cache.get_strategy(route)` (learned) falling back to `strategy.seed_strategy(route)` (declarative seed in `vasco/strategy.py`); it picks the *starting* tier only — it never decides whether the chain runs to completion. Content adapters (real-estate, google-shopping, olx) route their HTML fetch through this same chain via an injected `fetch_html`, so they share the strategy/seed system instead of hardcoding a browser-only fetch. They **opt out of the wayback recovery tail** (`allow_snapshot=False` in `_make_adapter_fetcher`): they parse live structured data, so an archived snapshot is stale and breaks their anchor — a blocked adapter fetch returns the honest `BLOCKED_*` failure rather than a plausible-but-stale snapshot. The mobile recovery tier (a live fetch) still applies, and an explicit `mode="wayback"` is still honored.
- **Empty content escalates on trafilatura `word_count`, not on raw-HTML heuristics.** `bot_detect.classify` sees only raw HTML, so it can't reliably tell an unrendered shell (escalate) from a thin-but-real page (keep): it both over-fired (a server-rendered VitePress page mounting into `id="app"`) and under-fired (Facebook ships ~1.2 MB of marker-less obfuscated script). So `classify` keeps **only** the high-precision *requires/enable-JavaScript notice* shell signal (e.g. MercadoLivre, whose no-JS boilerplate would otherwise convert to ~60 junk words); the authoritative "did anything render" verdict is the post-conversion `word_count`. In `_do_fetch_html`, an http-tier 200 in auto mode is converted **in the tier loop** (the conversion rides back on `_HtmlOutcome` so a *kept* http result is never converted twice — only an escalating shell pays a second conversion); `word_count == 0` escalates to the browser tier. If every content tier still yields zero words, `_fetch_one_body` emits the `EMPTY_BODY` failure. Content adapters opt out by fetching with `raw=True` (they parse embedded JSON, not prose, so a low prose-word count is meaningless for them). **Only HTML reaches trafilatura; raw text bypasses it.** Before that conversion the OK branch content-type-routes a `text/plain`-family body (`text/plain`/`text/markdown`/`text/x-markdown`/`text/x-rst` — `urlutils._is_plaintext_response`, with an HTML sniff so a *mislabeled* HTML doc still extracts) straight through verbatim via `convert.text_to_markdown` (mirrors `html_to_markdown`'s metadata shape, `boilerplate_ratio` 0, `plaintext_passthrough` warning). Trafilatura is an HTML *article* extractor — a raw `.md`/`.txt`/RFC/`LICENSE` has no DOM and converts to zero words, which would otherwise read as an unrendered shell and pointlessly escalate to the browser tier (or fail `EMPTY_BODY`). This sits alongside the binary-document routing (`_is_pdf`/`_pandoc_format`), so the four content classes — pdf, pandoc-doc, plain-text, html — each take their own path.
- **Phase timing is part of the envelope contract.** `duration_ms` is always stamped; `network_ms`, `parse_ms`, `cache_write_ms`, `attempts`, and `escalated_from` are populated on real fetches via the `_Phases` accumulator threaded through `_do_fetch_html` / `_fetch_pdf`. Cache hits and short-circuit paths stamp only `duration_ms`; `_hydrate_cache_hit` strips phase fields defensively. `telemetry.fetch_success_fields` surfaces them through the success event so `vasco logs stats` can roll up `phase_percentiles` and `escalation_rate`.
- **Telemetry has four outcomes.** `ok` / `fail` / `exception` / `empty` (the last for `extract` returning zero passages). Successes log too — disable the whole stream with `logging.enabled: false` or `VASCO_LOGGING_ENABLED=false`. Writes never block tool calls; I/O errors are swallowed. Content-adapter successes additionally carry `provider`/`page_type`/`result_count` (via `telemetry.fetch_success_fields` reading the envelope's `quality` block), so `logs stats` rolls up a per-provider `adapters` block with `zero_result_rate` — a high rate is the fingerprint of a silently-rotted adapter (still 200ing, parsing to nothing). `parse_failed` shows up in the failure histogram for free.
- **Negative-cache TTL is per-reason.** `fetch._FAILURE_TTL_MULTIPLIER` scales the base `failure_ttl_seconds` (default 900s) by failure reason. Permanent failures (`NOT_FOUND`, `ROBOTS_DISALLOW`, `INVALID_URL`) get ~24h; transient ones (`TIMEOUT`, `SERVER_ERROR`, `DNS_FAIL`, `PARSE_FAILED`) get ~5min. This keeps retries fast for flaky upstreams without hammering pages that genuinely don't exist. `PARSE_FAILED` is transient on purpose: scraper-rot is fixed by a code change (or the site reverting), so a redeployed adapter should heal fast instead of being pinned to a stale failure for a day.
- **HTTP-tier header profile is a per-domain strategy dimension (browser default / honest).** `_http_fetch(…, profile=)` builds headers via `_build_request_headers`: **`browser`** (default) sends the full modern-Chrome shape (`Sec-Fetch-*`, `Accept-Language`, `Accept-Encoding`, `Upgrade-Insecure-Requests` + configurable UA) to avoid WAF short-circuits that reject bare-UA requests before the browser tier; **`honest`** sends a minimal client set (plain UA + `Accept`, no `Sec-Fetch-*`) for WAFs that 403 the *half-fingerprint* — a "Chrome" UA without the rest of the suite reads as a headless bot (the GitLab self-hosted case). The profile is resolved per-fetch in `_do_fetch_html` (`_resolve_header_profile`) **exactly like the starting tier**: user `domains:` config (`DomainCfg`, exact host > registered domain) > learned (`cache.get/set_header_profile`, its own `route_header_profile` table) > code seed (`strategy.SEED_HEADER_PROFILES` / `seed_header_profile` — public GitLab hosts → honest) > `browser`. **Adaptive + learned**: on a `browser`-profile http block whose reason is a fingerprint rejection (`BLOCKED_CLOUDFLARE` — which a generic 403 maps to — or `BLOCKED_BOT`), the chain retries the http tier **once** with `honest` before escalating to the browser tier, and persists `honest` for the route on success (so the next fetch skips the retry). Self-healing is unchanged: a genuinely browser-only site still learns `preferred_mode="browser"` and `skip_http` stops both http profiles. (The GitLab *adapter* keeps its own httpx client — this is the general http tier.)
- **The browser tier is a separate peer service; the client only proxies.** Camoufox is **not** a dependency of core `vasco` — it lives in the `[browser]` optional extra and is imported only by `browser_server.py` (`vasco browser-server`). The fetch client (`vasco/fetch/browser.py`) never launches a browser: `get_browser(cfg)` returns a process-singleton `BrowserPool` (reset in tests via `browser._reset_for_tests()`) that forwards fetches to the server's UNIX socket. There is **no in-process fallback** — when the server isn't running, `BrowserPool` raises `BrowserServerUnavailable`, which `_browser_fetch` turns into the `BROWSER_UNAVAILABLE` failure reason (transient 0.33× TTL, not emitted by `bot_detect`) and the auto chain escalates to wayback instead of crashing. All browser config (locale, `user_data_dir` persistent_context for Cloudflare/login cookies, tracker blocking) is resolved **server-side** in `browser_server._build_launch_kwargs`; the client passes only URL + deadline + mobile flag, so `cfg` is ignored on the client. MCP's `VASCO_BROWSER_PREWARM=true` lifespan prewarm now just establishes the socket connection early; failures (server not running) are swallowed.
- **A persistent-profile login wall heals itself by clearing that domain's cookies.** A shared persistent profile accumulates session state that can flip a site into a login/account wall (MercadoLivre's `/gz/account-verification` interstitial is the motivating case). When `browser.clear_cookies_on_wall` (default on) and the profile is persistent, `browser_server._maybe_recover_login_wall` fires *server-side* (where the context lives), mirroring the Turnstile-solve precedent: a post-navigation page classifying `LOGIN_REQUIRED` triggers a **domain-scoped** `context.clear_cookies(domain=<registered_domain regex>)` + one re-navigation, returning the recovered page only if it no longer classifies as walled. Clearing is **never context-wide** — sibling sites' clearances (e.g. AliExpress `x5secdata`) must survive. Two loop guards make `wall → clear → wall` impossible to thrash: it is **single-shot** (one clear + one retry per `fetch_page`, no recursion) and **per-domain-cooldown-gated** (`_COOKIE_CLEAR_COOLDOWN`, so a persistent/non-cookie-gated wall can't make every later fetch re-clear). Recovery is transparent to the client/adapter (config-driven like the other recovery flags, no new wire field); an unrecoverable wall still crosses the wire as a `LOGIN_REQUIRED` failure (not the adapter's misleading `PARSE_FAILED`).
- **Browser-tier ad blocking is third-party-only and on by default.** `browser.block_ads` (default true) installs a `page.route("**/*")` handler in `fetch_page` that aborts requests whose `registered_domain` differs from the page's **and** match an ad/tracker hostlist (`vasco/fetch/netblock.py`). First-party requests (incl. same-site CDNs) always load, so a page's own resources are never dropped. The goal is **performance** — dropping third-party ad/tracker requests cuts page weight (fewer bytes, faster renders); as a bonus it also makes the headless browser look like a real adblock user, aiding rather than hurting the tier's anti-bot purpose. The list is resolved once off the event loop (`load_netblock` via `asyncio.to_thread`) at server startup — the handler itself is an O(1) frozenset membership test, and interception errors are swallowed so they can never kill a fetch. Default list is bundled (`data/netblock_default.txt`); `browser.network_blocklist_paths` points at local files or remote URLs (hosts/plain/uBlacklist formats) through the shared consolidate + 7-day-refresh loader. **Blocking happens entirely in `browser_server`** (which owns `fetch_page` and opens the page); the client just proxies, so there's no double-filtering and no new wire field — it's governed by the *server's* config. Decided against the uBlock *extension* (fingerprint surface, defeats stealth) and against EasyList ABP syntax (cosmetic rules N/A to request interception; network-rule subset needs a heavy parser). **Camoufox bundles uBlock Origin as a default addon and re-injects it on every launch** (`camoufox.addons.DefaultAddons.UBO`, restored even after a manual profile removal), so `_launch_locked` passes `exclude_addons=[DefaultAddons.UBO]` to keep the route-level netblock the *sole* blocker and honor that decision — without it the stealth tier silently runs the full uBO extension on top of the netblock.
- **Config precedence**: CLI flag > `VASCO_*` env var > `~/.config/vasco/config.yaml` > dataclass default. `cfg=None` is allowed everywhere internal — code falls back to defaults.
- **Quality scoring is two layers.** (1) Domain blocklist from community-curated files (uBlacklist + plain-domain formats); (2) text heuristics (slop vocab, sentence CV, em-dash density, transition starts, TTR) plus envelope metadata signals (boilerplate ratio, missing byline/date, thin content). Both produce signals merged into the envelope's `quality` dict alongside existing `trafilatura_confidence` and `boilerplate_ratio`. The composite `slop_score` (0-1, higher=worse) uses calibrated weights (15% text heuristics, 85% metadata — see `scripts/calibrate_quality.py`); the raw `signals` dict lets consumers apply their own thresholds. Blocklist is a lazy singleton (`quality.blocklist.get_blocklist`); reset in tests via `blocklist.reset()`. Quality scoring is enabled when `cfg.quality` is not None (the default); disable via `quality: false` in YAML or `VASCO_QUALITY_ENABLED=false`. Blocklist paths configured via `quality.blocklist_paths` (YAML list) or `VASCO_QUALITY_BLOCKLIST_PATHS` (colon-separated); accepts both local files and HTTP(S) URLs, consolidated to `$XDG_CACHE_HOME/vasco/blocklist.txt` with 7-day refresh.

## Testing

- Per-module unit tests in `tests/test_<module>.py`.
- **Cross-module integration tests** in `tests/test_fetch_integration.py` use a real `Cache` (sqlite in `tmp_path`) and stub only the network seam — `monkeypatch.setattr(core_mod, "_http_fetch"/"_browser_fetch", …)` where `core_mod = vasco.fetch.core` (the seam lives in `fetch.core`, re-exported from `vasco.fetch` for reads). Add to that file when fixing bugs that span modules — those are exactly the bugs unit tests with mocks per layer miss.
- Bot-detect tests are fixture-driven from `tests/fixtures/*.html`. Add a new fixture for any new failure signature.
- `asyncio_mode = "auto"` is configured in `pyproject.toml`, so `async def test_*` works without decorators.

## Conventions

- `from __future__ import annotations` at the top of every file.
- Type hints on public functions; docstrings only where the *why* is non-obvious.
- Failure handling: return failure envelopes, don't raise.
- Cache writes go through `Cache.put`; never INSERT/UPDATE the table directly.
- Don't add Claude/Anthropic co-author trailers to commits.
- When adding or renaming fields in any `*Cfg` dataclass, update `config.yaml.template` to match.
